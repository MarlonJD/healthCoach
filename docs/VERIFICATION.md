This document records scoped evidence for the checked-in source. It does not claim production readiness, device shipment, notarization, or App Store release.

## Environment

- Repository remained on the existing `main` branch.
- Swift toolchain: Xcode 27.0, build 27A266a; the plan specifies Xcode 26.6 and the project targets Apple platform version 26.0.
- Codex CLI: `codex-cli 0.154.0-alpha.6.2`; `codex login status` reported an existing ChatGPT sign-in.

- A real Network.framework loopback listener/client exchange accepted the valid pairing PSK and rejected the wrong credential. The framing tests also reject malformed and oversized frames.
- The signed Mac companion was installed and launched locally with its packaged MCP helper and Bonjour listener. Pending QR rotation is implemented in the live Mac model with a 30-second renewal lead time; the frame decoder was hardened after a physical pairing attempt exposed an out-of-bounds Data slice crash, and its multi-frame arbitrary-chunk regression test passes.
- The real `healthcoach-mcp` executable initialized over official MCP Swift SDK stdio, listed the exact nine read-only tools, and served bounded reads from a synthetic SQLite store. The compatibility stdio transport removes only the unsupported object-valued experimental capability from the current Codex initialize request; all HealthCoach tool behavior remains on the official MCP SDK.
- A direct App Server protocol probe using the installed binary completed `initialize`, `mcpServerStatus/list`, and synthetic no-model `thread/start` with the same `--strict-config --disable apps` process arguments used by the Mac adapter; the effective `healthcoach` server exposed the exact nine-tool catalog even while reusing the existing sign-in. The client parser handles the installed CLI's native JSON `NSArray`/`NSDictionary` representation.

This verifies the Mac queue completion path after the nested `turn.id` parser fix.
- A live arm64 Mac companion observation showed two independent job-scoped App Server/MCP process pairs running concurrently. A turn that reached the 300-second bound was persisted as `deadLettered`, and the queue monitor picked up subsequent pending work; old `failed` records were normalized into the same durable DLQ state.
